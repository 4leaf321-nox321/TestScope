# 검토함, 요청, VOC

카탈로그와 온톨로지 수정은 시스템 관리자 전용임. 그 외 사용자는 아래 경로로 등록 또는 변경을 요청함.

| 경로                    | 작성                         | 결정          | 용도                                                   |
| ----------------------- | ---------------------------- | ------------- | ------------------------------------------------------ |
| [검토함](/admin/review) | 모든 사용자(의견)            | 시스템 관리자 | 반입 과정에서 미확정된 항목(규격의 시험 항목, 조건 등) |
| 시험 항목 요청          | 신뢰성 시험 편집 권한자(MCP) | 시스템 관리자 | 시험 항목 축에 없는 시험 항목                          |
| 기종 등록 요청          | 모든 사용자                  | 시스템 관리자 | 카탈로그에 없는 기종                                   |

- 검토함은 ‘공통’ 메뉴에 위치함. 의견 작성은 모든 사용자가 가능하며, 확정은 시스템 관리자 전용임(화면, MCP 모두 가능).
- 요청은 같은 표기끼리 묶여 표시됨. 결정 결과는 요청한 장비 또는 시험 전체에 일괄 적용됨.
- 결정 방식은 기존 값 연결, 신규 등록, 거절 중 하나임.

## 의견, 보류, MCP 의견

- 보류할 때 사유(근거 부족, 도메인 전문가 확인 필요, 원문 확인 필요, 후보에 맞는 답 없음, 기타)와 메모를 남김. ‘보류됨’ 목록에 사유·메모·보류한 사람이 표시되고, ‘보류 해제’로 되돌림.
- MCP로 낸 의견과 확정은 이름 뒤에 ‘(MCP)’가 붙음. 의견 수 옆에 MCP 의견 수가 표시됨.
- ‘MCP 의견만’을 켜면 MCP 의견이 있는 줄만 표시됨. MCP 의견이 하나로 모이고 다른 사람 의견이 그와 같은 줄은 골라서 ‘MCP 의견대로 확정’으로 한꺼번에 확정 가능(MCP로는 AI 도구의 확인 창에서 수락 후). MCP 의견이 갈리거나 사람 의견이 다른 줄은 확정하지 않고 사유와 함께 돌려줌.
- 의견은 사람마다 하나임. 같은 사람이 화면과 MCP로 각각 내면 나중 것으로 바뀜.

## 후보의 근거와 경고

- 추천은 후보마다 자기 근거가 있을 때만 붙음. 근거 문장과 출처가 후보 옆에 표시됨.
- 경고가 붙은 후보는 추천하지 않음. ‘분류와 맞지 않음’은 같은 장비 분류의 다른 계열이 아무도 하지 않는 시험임. ‘카탈로그 ○○와 같은 규격(표기만 다름)’은 고르면 새 규격이 생기는 표기임.
- 계열 시험 항목 추가의 제조사 페이지 근거는 장비 이름과 시험이 같은 문장에 나온 것만 셈.
- 같은 계열이 출처만 달리해 두 줄로 뜨던 것은 한 줄로 합쳐 표시됨(근거·출처 함께 표시). 이미 두 줄이 있으면 한쪽을 확정할 때 다른 쪽도 같은 결정으로 닫힘.
- 후보 밖에서 고른 항목도 결정 완료 목록에 이름으로 표시됨.

## 계열 인용 규격

- 판 표시만 다른 후보(ASTM D638-14 등)는 카탈로그의 정식 규격(ASTM D638)으로 묶여 그 규격이 앞에 표시되고 추천도 그리로 감. 카탈로그에 없으면 판을 뗀 번호 하나로 묶임.
- 후보에 없는 규격은 ‘직접 입력’에 번호를 적어 의견·확정 가능. 카탈로그에 있는 번호(옛 번호 포함)면 그 규격에 연결되고, 없으면 새 규격이 생김.
- 판 표시만 다른 규격이 둘 생기면 ‘규격 목록 정리’ 검토함에 정식 규격으로의 병합 후보로 표시됨. 규격 화면의 ‘다른 규격으로 병합’으로도 합칠 수 있음(시스템 관리자, 사유 기록). 합친 쪽 번호는 남는 규격의 옛 번호가 되어 반입·검색·검토함이 계속 찾음.

## 시험 항목 코드

- 시험 항목과 물성은 코드로 고름. 값을 만들 때 코드를 비우면 `custom_001` 형식으로 자동 생성됨. 같은 이름의 정본 값이 반입되면 정본 코드로 바뀜.
- 코드를 적을 때 규칙: 공백 없이 2~120자. 권장 꼴은 영문 소문자·숫자·밑줄(예: `tensile`, `vibration_sine_random`), 물성은 분야.이름(예: `mechanical.tensile_strength`).

## 규격의 시험 항목

- 후보는 이 규격을 인용한 계열이 이미 수행하는 시험 항목(또는 다른 판·규격 제목의 근거)임.
- 확정하면 인용 계열 중 그 시험 항목을 가진 계열에만 연결됨. 후보 밖 항목을 고르면 그 시험 항목이 없는 계열은 연결되지 않음.
- 연결되지 않는 계열이 있으면 확정 전에 확인 창이 뜸. ‘인용 계열에 시험 항목 추가 후 확정’ 또는 ‘연결 없이 확정’ 중 선택.
- 연결 없이 확정한 규격은 홈 ‘남은 일’의 ‘시험 항목은 정했는데 인용 계열에 안 이어진 규격’과 시험법 목록의 ‘인용 계열 미연결’ 필터에 표시됨. 규격 화면의 ‘인용 계열에 시험 항목 추가’로 연결 가능(시스템 관리자).
- 다시 열어 다르게 확정하면 교체임. 빠지는 시험 항목으로만 이어진 계열은 끊기며, 확정 전 확인 창에 표시됨.
- 잘못 걸린 시험 항목은 규격 화면의 시험 항목 옆 ‘×’로 해제(시스템 관리자, 사유 필수·감사 기록). 해제 전에 끊기는 계열 수와 이름이 표시됨. 끊긴 계열은 ‘인용 계열 미연결’로 돌아가고, 남은 시험 항목이 없으면 검토함 질문이 다시 열림.

## 사양 정의 승격

- 범위 정의는 ‘0 ~ 10’, ‘min 0 · max 10’, ‘max 10’, ‘10’(상한) 표기를 읽음.
- 승격을 확정하면 먼저 옮겨질 값과 남을 값(기종: 값)이 표시됨. 옮길 값이 하나도 없으면 승격이 거절되며, ‘유지’로 결정하거나 ‘상세’의 기종 화면에서 값을 고친 뒤 다시 확정함.
- 결정 완료 줄과 기종 화면에 옮기지 못한 값이 표시됨(기종 화면: ‘정식 칸으로 옮기지 못함’).

## 카탈로그 보강

[카탈로그 보강](/admin/catalog-gaps)(관리 메뉴, 시스템 관리자 전용)은 카탈로그 기종에 연결되지 않은 장비 전체를 사유별로 분류한 목록임. 요청이 없는 장비도 포함됨. 같은 제조사·모델명 표기는 한 묶음으로 표시됨.

| 사유               | 판정 기준                                        | 조치                                         |
| ------------------ | ------------------------------------------------ | -------------------------------------------- |
| 같은 기종 있음     | 같은 제조사 안에 같은 기종 번호의 기종 존재      | 확인 후 연결                                 |
| 비슷한 기종 있음   | 이름이 유사한 기종 존재(다른 기종일 수 있음)     | 같은 기종이면 연결, 아니면 후보 계열에 등록  |
| 계열만 있음        | 계열 이름 또는 기종 번호 앞부분 일치, 기종 없음  | 계열에 기종 등록                             |
| 카탈로그에 없음    | 제조사 또는 계열이 카탈로그에 없음               | CSV 내려받아 제조사 사양서 조사 후 정본 반입 |
| 모델명 없음        | 장비의 모델명이 비어 대조 불가                   | 장비 화면에서 모델명 입력                    |
| 카탈로그 대상 아님 | 시스템 관리자가 대상 아님으로 결정(자작 장비 등) | 조치 불필요                                  |

- 후보 기종은 이름 비교 결과일 뿐 같은 기종이라는 판정이 아님. 연결 전 확인 창에서 기종 확인 필수.
- 연결, 계열에 등록, 대상 아님 결정은 기종 등록 요청을 만든 뒤 결정하는 것과 같음. 결정 기록이 요청과 변경 이력에 남음.
- ‘요청으로 올리기’는 결정 없이 기종 등록 요청만 등록함.
- 분류별 현황의 ‘정본에 분류 없음’은 운영에서 직접 만든 분류임. 카탈로그 정본(`source/catalog`)에 분류 추가가 먼저 필요함.
- CSV에는 묶음별 자산번호 전체가 포함됨. MCP에서는 `list_model_requests(gaps=True)`로 조회 가능.

## 열린 축과 닫힌 축

| 구분    | 예시                    | 값 추가                            | 이름 변경·병합 |
| ------- | ----------------------- | ---------------------------------- | -------------- |
| 열린 축 | 제조사, 거점, 장비 유형 | 모든 사용자                        | 시스템 관리자  |
| 닫힌 축 | 시험 항목               | 시스템 관리자(그 외 사용자는 요청) | 시스템 관리자  |

- 축 생성은 시스템 관리자 전용임.
- 값의 이름 변경과 병합은 해당 값을 사용하는 모든 화면에 반영됨.

## VOC

화면 오류와 기능 개선 요청은 [VOC](/voc)에 등록함. VOC는 로그인한 모든 사용자에게 공개됨.

    등록 → 접수 → 처리 중 → 해결 → 종료
                        └→ 반려

- 해결 또는 반려 시 처리 내용이나 사유 입력 필수.
- 종료 확인은 등록자가 수행함. 해결되지 않은 경우 다시 열기 가능.
- 등록 시 대상 식별 정보 기재(자산번호, 기종명, 시험 이름 등). 파일 첨부 가능.

서비스 중단, 신규 기능 등 운영 안내는 [공지](/notices)에서 확인.
