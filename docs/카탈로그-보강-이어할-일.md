# 카탈로그 보강 — 이어 할 일 (2026-09-13 기준)

`source/catalog_extension/` 에 제조사 웹·남의 페이지·논문을 모아 두었고(README 참고), 그것으로 검토함
「계열이 하는 규격 더하기」 「계열이 하는 시험 더하기」 「계열 소개에 넣을 문장」 물음을 세웠다. 아직 못 한 것과, 그 다음 순서.

## 1. OpenAlex — 끝 (2026-09-15)

OpenAlex(openalex.org — 학술 논문 메타데이터 공개 API, Claude 와 무관한 외부 서비스)는 키 없이 하루
요청 예산(약 100건)이 있어 사흘에 걸쳐 받았다: 278/278. 새 객체가 생기면 `tools_harvest_papers.py` 를
다시 돌리면 그 객체만 받는다(예산에 걸리면 다음 날 `--fill-openalex`).

## 2. 한 쪽도 없는 객체 — 끝 (2026-09-15)

278 객체 전부 한 쪽 이상 있다(2,073쪽). 새 객체가 생기면: 「제조사 기종 applications」 로 검색해 대리점·
대학 장비실·리뷰 페이지 5~8개를 `source/catalog_extension/extra_urls.json` 에 넣고

    cd source/catalog_extension
    python tools_harvest.py --extra        # 있는 주소는 건너뛰고 새 것만 받는다
    python tools_propose.py
    cd ../../backend && python scripts/refresh_review.py

검색 엔진을 스크립트로 부르는 것은 안 된다(봇 확인 페이지가 온다 — README 에 실측). Claude 의 웹 검색은
세션당 200회.

## 3. 그 다음 — 검토함으로 보강을 실제로 반영하기

1. 도메인 전문가가 검토함에서 고른다 — 「계열이 하는 규격 더하기」(203 계열 · 후보 1,880), 「계열이 하는
   시험 더하기」(101 · 246), 「계열 소개에 넣을 문장」(162 · 285). 후보마다 출처 링크·인용문이 있다 —
   대리점 목록 페이지는 옆 제품의 규격일 수 있고, 논문 문장은 옆 장비 얘기일 수 있으니 읽고 고른다.
2. 확정된 것은 DB 에 바로 붙는다. `backend/scripts/export_review.py` 로 정본
   `source/catalog/proposals/series_*.json` 의 `decided` 에 되돌려 쓴다 → 운영 반입 때 자동 적용.
3. 규격이 붙으면 「규격의 시험 항목」 물음이 늘 수 있다(시험이 여럿인 계열에 붙은 규격) — 같이 처리.
