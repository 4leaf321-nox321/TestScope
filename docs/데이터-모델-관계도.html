TestScope 데이터 모델 관계 정의

카탈로그 영역(장비 계열 · 장비 기종 · 시험 항목 · 시험법/규격 · 물성 항목)과 사내 운영 영역(신뢰성 시험 · 보유 장비 · 부서)의 관계 정의. 기준: v0.6.7 (2026-09-16) 코드의 외래키 구조. 표 이름은 실제 DB 표. 그 뒤에 더해진 관계는 6절에 있고, 살아 있는 그림은 화면의 「공통 → 지식 그래프」 가 실제 건수와 함께 그린다 — 이 문서는 관계의 이유를 적는 자리다.

핵심 질의     "80 ℃ 환경에서 20 kN 이상의 인장시험이 가능한 장비의 유무"

    물성 항목  ⇄  시험 항목  →  검색 조건·요구 조건  →  시험법/규격  →  장비 계열  →  장비 기종  →  보유 장비  →  부서
    인장강도       인장          온도 80 ℃ · 하중 20 kN     ISO 6892-1       Instron 6800     68FM-300       UTM-001       재료시험팀

사내 운영 층   신뢰성 시험(부서 등록 절차: 고온고습 1000h · 열충격 500 cycle)  →  구성 시험 항목  →  위 사슬

1. 관계 개요

읽는 법 — 화살표는 참조 방향(참조하는 표 → 참조되는 표). 실선은 외래키 참조, 점선은 복사 또는 파생. 번호 ①~⑬은 아래 「2. 관계 정의」 표의 번호와 동일. 선 위의 글은 관계의 뜻, 괄호는 차수.

기준정보 축 (값 · 별칭 · 코드)카탈로그 (반입으로 적재)조건 · 사양 정의 (검색 축)사내 운영 데이터 (부서 등록)

5. 관계 설계 원칙

  • 3계층 분리 — 계열의 수행 가능 시험 · 기종의 수치 사양 · 개체의 실제 수행 시험 (ADR 0004 · 0006).
  • 복사와 중첩 조회의 구분 — 시험 항목은 개체로 복사(시점 스냅샷), 사양은 기종 값 위에 상이한 개체 값만 중첩(사양서 값과 실측 값의 병존).
  • 관계의 표 저장 — 규격 인용 · 계열 관계 · 물성 연결 전부 연결 표. 비고 텍스트는 검색 불가.
  • 미상과 불충족의 구분 — 조건 부재는 「조건 미상」, 시험 항목 미지정 규격은 「검색 불가」로 별도 표시.
  • 제안과 확인의 구분 — 물성 연결 상태 · 시험 항목 신뢰도(confidence) · 검토함 결정 모두 기계 제안과 사람 확인을 별도 값으로 보존.
  • 삭제 금지 — 장비 · 규격 · 신뢰성 시험 · 계정은 deleted_at 설정(소프트 삭제). 외부 산출물의 참조 보존.
  • 신뢰성 시험의 상위 층 배치 — 하위 사슬(시험 항목 → 조건 → 규격 → 장비) 불변, 그 위에 절차 층 추가.

6. v0.6.7 이후 더해진 관계 (v0.14.0 기준)

아래는 원래 그림에 없던 표와 선이다. 그림을 다시 그리지 않은 이유는 「공통 → 지식 그래프」 가 이 관계 전부를 정의(graph/model.py)에서 읽어 실제 건수와 함께 그리기 때문이다 — 관계의 정본은 그 파일 하나다.

관계구현기수정의 근거
⑭객체 → 속성 값
관리자가 정의한 칸		attribute_definitions(대상 · 종류 · 초안/정식) · attribute_values(reliability_test_id | equipment_id | series_id | method_id 중 하나)1 : N칸을 열이 아니라 행으로 둔다 — 조사 중인 칸을 열로 뚫으면 안 쓰는 열이 남고 두 사람이 각각 더하면 갈린다. 초안은 온톨로지 밖(검색·판정·색인 카드에 안 듦), 정식으로 올리는 문 하나. 이름이 갈린 초안은 검토함 「초안 속성 정리」 가 사람에게 묻는다.
⑭′속성 정의 → 검색 조건 축
조건 속성		attribute_definitions.condition_key_id (kind=condition)N : 1조건을 검색축과 같은 축·같은 차원으로 적어야 「이 시험을 돌릴 장비」 판정이 성립한다. 신뢰성 시험의 조건 속성은 그대로 ConditionQuery 가 되어 장비 찾기(②·⑩)에 넘어간다 — 판정 규칙은 두 벌이 아니라 하나(reliability/capability.py).
⑭″속성 값 → 기준정보 값 · 규격
참조 속성		attribute_values.term_id (kind=term) · ref_method_id (kind=method)N : 1값이 글자가 아니라 참조라야 갈리지 않는다. ref_method_id 는 「값이 가리키는 규격」 이고 method_id 는 「이 값이 붙은 규격」 — 다른 열이다.
⑮검토함 줄 → 대상
사람이 정할 것		review_proposals(queue · subject_key · subject_id) · review_votesN : 1반입이 못 정한 것(어느 시험의 규격인가 · 무슨 조건을 묻나 · 이 물성이 나오나 · 초안 속성을 합칠까)을 후보·추천·근거와 함께 둔다. 의견(누구나)과 확정(시스템 관리자)을 가르고, 확정은 기계 자격으로 막혀 있다(403) — 고른 것이 곧 정본이라. 대상이 지워진 줄은 「대상 없어짐」 으로 따로 닫는다.
⑯물성 연결의 출처
제안 · 확인		test_item_properties.status(suggested | confirmed) · source(ontology | materialtwin | manual | agent)—①에 열 둘. AI 가 낸 연결은 언제나 suggested·agent 로 들어오고 사람이 확인한다 — 확인은 「사람이 봤다」 는 뜻이고 카탈로그 정본에 실리므로 기계가 대신 못 한다.
—지식 그래프
관계의 정본		graph/model.py 의 EDGE_KINDS — 위 관계 전부를 (원본 종류 · 대상 종류 · SELECT) 한 줄씩—새 관계는 거기 한 줄이고 구조·이웃·subgraph·노드 상세가 전부 그 목록을 돈다. 화면마다 관계를 따로 적으면 「그림에는 있는데 상세에는 없는」 선이 생긴다. 장비는 visible_equipment_ids 로 걸러 가린 부서의 것은 어디에도 안 선다.
