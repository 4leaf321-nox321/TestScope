# 0012. **기준정보 허브(StandardPlatform)에서 기준정보를 받는다** — 0011 대체

## 결정

TestScope 는 StandardPlatform 기준정보 허브의 코어 API(`/api/core`)에서 **공개된 코어 타입 전부**를
받는다. 사용자 결정(2026-10-21): **"받아와도 될 거 같아. 보안상 문제 없어. 받는 모듈을 만들자."**
2026-10-08 의 「보안상 받지 않는다」(ADR 0011)를 대체한다.

기준은 허브 운영의 「코어 데이터 수신 모듈 개발 요청서」 1.2 판(2026-10-14, `F:\CrossTF보고서\
온톨로지개발요청서\`)이다 — 필수 FR-01 ~ FR-13, 인수 시험 AT-01 ~ AT-15. 허브는 WSL
`~/projects/StandardPlatform`(0.4.58, `backend/app/modules/coreapi`)에서 계약을 확인했고, 구현
사례는 ReportArchive `connectors/sp_core.py · sp_pull.py` 다.

함께 정한 넷(2026-10-21):

1. **받을 것은 카탈로그의 공개 타입 전부.** 개발 허브에는 PLM 넷(프로젝트 · 과제 · 개발모델 · 시험
   주체)뿐이지만 운영 허브에는 훨씬 많다. 타입명을 코드에 고정하지 않는다 — 관리 화면에서 고르지
   않으면 「전부」 이고, 허브가 타입을 새로 열면 다음 수신에 저절로 들어온다.
2. **시험 · 장비에 잇는 것은 운영에서 MCP 로 한다.** 그래서 기계 자격이 그것을 할 수 있어야 한다(4).
3. **야간 1회 01:00 KST, 실패 알림은 시스템 관리자 전원.**
4. **처음부터 적용한다** — 「미리보기 후 적용」(FR-16, 권장)은 두지 않는다.

그리고 사용자가 고른 것 하나: **확정된 신뢰성 시험에도 허브 칸만은 기계 자격으로 붙이고 뗀다.**
확정은 그 시점 내용의 보증이라 기계 자격의 수정을 막는데(ADR 0009), 개발모델 · 과제를 잇는 것은
시험 내용이 아니라 분류 표시다. 다른 칸을 섞으면 종전대로 409 다.

## 어떻게

| 자리 | 무엇 |
|---|---|
| 저장(방식 A) | `core_items` · `core_relations` — 받은 원문. 물리 삭제 없음. 부재 대조 · 감사 대조의 근거 |
| 반영(방식 B) | 타입마다 온톨로지 축 `hub_<타입>`(도메인 `hub`), 객체마다 값(코드 = 허브 식별자, 별칭 = 옛 식별자) |
| 잠금(FR-10) | `vocabularies.hub_type_slug` 가 차 있으면 값 추가 · 수정 · 별칭 · 병합이 409 `TSC-VOCAB-0020` |
| 수신 | `hub.sync` — 카탈로그 → 참조 대상 타입부터 행 · 관계, 타입 단위 트랜잭션, `as_of` 는 다 받은 뒤에만 |
| 실행 | 워커의 작업 `hub.sync` — 야간(설정 시각) · 수동 · 7일마다 전량 대조, 동시 실행 방지 |
| 토큰 | Windows DPAPI(기계 범위 + `JWT_SECRET` 엔트로피)로 봉인해 DB 에. 화면 · 로그에 안 나온다 |
| 화면 | 관리 › 허브 연계(설정 · 현황 · 이력), 공통 › 허브 기준정보(누구나 조회) |
| 시험 · 장비 연결 | 「값 고르기」 칸이 허브 축을 가리키면 허브 칸. 기계 자격이 허브 칸만 보내면 그 칸만 바뀐다 |

**새 의존성은 없다.** 토큰 암호화에 `cryptography` 대신 DPAPI 를 쓴다 — 운영 · CI · 개발이 모두
Windows 다. 대가는 DB 를 다른 PC 로 옮기거나 `JWT_SECRET` 을 바꾸면 토큰을 다시 입력해야 한다는
것이고, 화면이 그때 「다시 입력」 을 말한다.

**웹훅(FR-17, 선택)은 두지 않았다.** 허브 → TestScope 로 들어오는 접속을 열어야 하고, 주기 수신으로
요건이 찬다.

## 식별자가 없는 타입

허브는 식별자가 없는 타입의 `key` 를 이름으로 대신 준다(비고유 · 가변, 요청서 §5.4). 카탈로그에는
그것을 가르는 표식이 없어 TestScope 도 가르지 않고 받는다. 이름이 바뀌면 새 객체처럼 들어오고 옛
것은 주간 전량 대조에서 「부재」 로 비활성된다. 허브가 식별자를 필수로 바꾸면 그 뒤로는 식별자
변경으로 들어온다.
