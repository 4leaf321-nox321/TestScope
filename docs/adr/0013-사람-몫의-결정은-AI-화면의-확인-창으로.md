# 0013. **사람 몫의 결정은 AI 화면의 확인 창으로도 한다** — 0009 의 「사람만」 을 넓힌다

## 결정

사용자 결정(2026-10-22): **"화면에서 결정 안 하고, 웬만하면 AI 가 다 결정할 수 있게 하고 싶어. AI
에 모두 오픈해 줘. 대신, 결정할 내용을 AI 화면에서 확인받는 형태로."** 함께 고른 둘:

1. **비밀값은 뺀다** — 토큰 발급 · 폐기, 임시 비밀번호(계정 만들기 · 비밀번호 초기화), 허브 토큰
   입력은 어떤 확인으로도 기계 자격에 안 연다. 열면 평문 비밀이 AI 대화 기록에 남는다.
2. **확인 창을 띄울 수 있는 클라이언트만** — 확인 창(MCP elicitation)이 없는 클라이언트에서는 사람
   몫의 결정을 실행하지 않는다. 「대화로 물어보고 진행」 은 허용하지 않는다: AI 가 사용자의 답 없이
   진행하는 것을 서버가 막을 길이 없다.

그래서 **「화면에서만」 이던 것이 「사람이 확인한 것만」 이 된다.** 화면에서 누르는 것과 AI 화면의
확인 창에서 수락하는 것은 둘 다 사람의 확인이다.

| 이제 확인 창을 거쳐 AI 가 하는 것 | 막는 자리(서버) |
|---|---|
| 신뢰성 시험 확정 · 반려 · 다시 후보로 · 개정 확인 | `reliability._human_only` · `bulk` (TSC-RELIABILITY-0006) |
| 확정된 신뢰성 시험 수정 · 삭제 | `reliability._refuse_machine_edit` (0005, 허브 칸만은 확인 없이 — ADR 0012) |
| 검토함 MCP 의견대로 일괄 확정 | `review.decide_by_mcp_votes` (TSC-REVIEW-0022) |
| 규격 병합 · 규격의 시험 항목 해제 | `methods.merge_by_admin` · `detach_test_item` (TSC-METHODS-0021 · 0020) |
| 장비 일괄 삭제 | `equipment.bulk_delete` (TSC-EQUIPMENT-0048) |
| 계정 · 부서 · 멤버 · 공지 · 허브 연계 · VOC | `auth._CONFIRMED_WRITES` + 범위 `admin:write` (TSC-AUTH-0107) |

## 어떻게

**증표는 MCP 서버만 만든다.** 흐름은 셋이다.

1. MCP 도구가 요청을 **그냥 보내 본다.** 사람 확인이 필요하면 서버는 아무것도 안 바꾸고 거절하며,
   확인 창에 실을 요약(`details.confirm` — 시험 이름 · 칸마다의 값 · 건수 · 사유)을 준다. 표식은
   코드가 아니라 `details.needs_confirmation` 이다(막는 자리마다 코드가 다르다).
2. MCP 서버가 그 요약과 AI 가 보낸 값을 **확인 창**으로 띄운다. SDK 의 해석기(`Resolve` + `Elicit`)
   를 쓴다 — 구 프로토콜은 요청 중에 되묻고, 새 프로토콜(2026-07-28)은 「입력 필요」 결과로
   되묻는다. 해석기는 차례마다 다시 돌 수 있으므로 1 의 「보내 보기」 는 거절될 때 부작용이 없어야
   한다(그래서 거절은 바꾸기 전에 한다).
3. 사람이 수락하면 MCP 서버가 **같은 요청**에 서명해 `X-Human-Confirm` 으로 싣고 다시 보낸다.
   서명은 메서드 · 경로 · 쿼리 · 토큰 해시 · 본문 해시에 걸리고, 2분 뒤 만료, 한 번만 쓴다. 열쇠는
   `JWT_SECRET` 에서 뽑는다(`backend/app/shared/confirm.py` · `mcp_server/confirm.py`, 두 벌이라
   시험이 맞대 본다). 백엔드는 앱 전역 의존성(`confirm.read_proof`)으로 검증하고 그 요청을
   「확인됨」 으로 표시한다 — 감사의 통로가 `mcp:confirmed` 가 된다.

**증표는 권한이 아니다.** 호출자의 토큰에 묶이고 토큰 없이는 아무것도 인증하지 않는다. 범위와
자격(시스템 관리자 · 부서 관리자)은 종전대로 서버가 본다. 그래서 만능 토큰을 두지 않는다는 규칙
(AGENTS.md)은 그대로다 — MCP 서버는 여전히 제 자격으로 아무것도 부르지 않는다.

관리 경로는 범위 `admin:write` 를 따로 둔다. 증표만으로 충분하지만, 관리를 AI 에 맡길지를 토큰을
만드는 사람이 **고르게** 하려는 것이다.

## 왜 이렇게

- **「사람만」 의 이유는 「AI 가 혼자 정하지 않는다」 였다**(ADR 0009). 화면은 그것을 지키는 한
  방법이었지 이유가 아니었다. 확인 창에서 사람이 바뀌는 내용을 보고 수락하면 그 이유는 지켜진다.
  대신 창에는 **내용**을 싣는다 — 「확정합니까」 만 물으면 무엇을 확정하는지 모른 채 누른다.
- **서버가 막는다.** 도구 설명에 「사용자에게 물어라」 라고만 적으면 AI 가 건너뛸 수 있고, PAT 로
  경로를 직접 부르면 도구 설명은 아무것도 못 한다. 증표는 확인 창을 거친 MCP 서버만 만든다.
- **판정이 한 곳이다.** 「확인이 필요한가」 를 따로 묻는 엔드포인트를 두지 않는다 — 막는 자리에서
  거절하며 요약을 실어 보내고, MCP 는 그것을 그대로 창으로 옮긴다. 두 벌이면 갈라진다.

## 대안

- **대화로 확인(미리보기 → 「확인」 이라 답하면 진행)** — 지원하는 클라이언트가 더 많지만, AI 가
  사용자의 답 없이 진행하는 것을 서버가 가릴 수 없다. 사용자가 고르지 않았다.
- **URL 확인(elicit_url — TestScope 화면의 확인 페이지로 보내기)** — 더 강하지만 결국 화면으로
  가는 것이라 요청의 취지(화면에서 결정 안 함)와 어긋난다.
- **토큰에 「결정」 범위 하나로 열기** — 사람 확인이 없어 0009 를 버리는 것과 같다.

## 결과

- MCP 도구 96 → 98: `decide_reliability_tests` · `admin_action`. 확정된 시험 고치기 · MCP 의견대로
  확정 · 규격 병합 · 시험 항목 해제 · 일괄 삭제는 있던 도구에 확인 창을 달았다.
- 확인 창이 없는 클라이언트는 이 결정들을 못 한다(오류 문장으로 거절, 실행 안 함). 화면은 그대로다.
- `mcp_server/roundtrip.py` 가 흉내 창(수락 · 거절)과 **실제 SDK 클라이언트**(구 · 신 프로토콜)로
  왕복한다. 증표는 진짜라 MCP 서버와 백엔드의 열쇠가 어긋나면 CI 가 잡는다.
- 클라이언트가 확인 창을 사람에게 보이지 않고 스스로 답하게 설정돼 있으면 이 보증은 없다 — 그것은
  클라이언트를 쓰는 사람의 설정이다(Claude Code 는 창을 사람에게 띄운다).
