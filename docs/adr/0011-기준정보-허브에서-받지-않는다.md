# 0011. **기준정보 허브(StandardPlatform)에서 기준정보를 받지 않는다**

## 결정

TestScope 는 StandardPlatform 기준정보 허브의 코어 API(`/api/core`)에서 기준정보를 **받지
않는다** — 수신 모듈 · 허브 토큰 · 허브 주소 설정 어느 것도 두지 않는다. 사용자 결정
(2026-10-08): **"보안상 여기서 받으면 안 된다."**

TestScope 가 허브로 **주는** 방향은 닫지 않는다. 다만 **보안 검토를 거친 뒤에만** 설계한다
(아래 「주는 방향」).

## 배경

허브 운영 쪽이 「코어 데이터 수신 모듈 개발 요청서」(1.1, 2026-10-06,
`F:\CrossTF보고서\온톨로지개발요청서\`)를 냈다. TestScope 는 거기서 **신규 구현** 대상이고,
1차 수신 대상은 PLM 기준정보 넷 — 프로젝트(`plm_project`) · 과제(`plm_task`) ·
개발모델(`plm_model`) · 시험 주체(`plm_test_site`) — 이다. 필수 기능은 FR-01~13(연계 설정 ·
증분 수신 · 삭제/병합/식별자 변경 반영 · 수신 전용 잠금 · 야간 실행 등), 인수 시험은
AT-01~15 다. ReportArchive 의 설계 문서(`[미구현] 기준정보_교환_설계.md`)는 한 걸음 더
나가 「TestScope 의 물성 축 시드를 허브 pull 로 대체」 까지 적어 두었다.

조사한 사실(2026-10-07):

- 실제 허브는 WSL 의 `~/projects/StandardPlatform`(v0.4.44)이다. `F:\data\0_Program\
  70_StandardPlatform` 은 9월 10일자 옛 틀이라 코어 API 가 없다.
- 운영 허브는 Linux 서버에서 `https://hwax.sec.samsung.net/<APP_SLUG>/`(예정 `plmhub`)로
  뜨고, TestScope 운영은 Windows PC 다 — 받으려면 TestScope PC 에서 허브로 나가는 HTTPS 와
  허브가 발급한 `core:read` 토큰이 필요하다.
- ReportArchive 에는 같은 수신 모듈(`connectors/sp_core.py` · `sp_pull.py`)이 있으나 실제
  허브에는 아직 안 붙었다. 개발 허브에는 공개된 코어 타입이 0개였다.

## 받지 않아도 잃는 것이 적다

TestScope 가 답하는 물음은 「이 시험이 되는 장비가 우리 조직에 있나」 다. 그 사슬(시험 항목 ·
시험법 · 장비 계열/기종 · 조건 축 · 보유 장비)은 **TestScope 가 정본**이고, 허브 설계 문서도
이것들을 「공통이 아님 — TestScope 소유」 로 분류한다. 허브가 주려던 PLM 넷(개발모델 · 과제 ·
프로젝트 · 시험 주체)은 그 사슬 밖이다 — 신뢰성 시험이나 장비에 「대상 개발모델」 칸을 다는
정도의 쓰임이었다. 부서는 원래 ReportArchive 가 정본이고, TestScope 는 지금처럼 그
내보내기 파일로 들인다(`workspaces/imports.py`, 사람이 미리보기 후 적용).

물성 축(MaterialTwin 271 키)은 지금처럼 카탈로그 정본(`source/catalog/ontology/
properties.json`)에서 반입으로 심는다. 허브 pull 로 바꾸지 않는다.

## 주는 방향 — 검토 후에만

허브 요청서 §2.3 은 「플랫폼 → 허브 역방향 송신: 별도 요청」 이라 적고 있다. 줄 수 있는
후보는 TestScope 가 정본인 것(시험 항목 · 시험법 · 장비 계열/기종 · 조건 축)이고, 보유
장비 · 부서 · 신뢰성 시험 같은 사내 운영 데이터는 **넘길지부터** 검토 대상이다. 방식은 둘 중
하나로 본다.

| 방식 | 보안 측면 |
|---|---|
| 내보내기 파일(관리자가 내려받아 검토 후 전달) | 네트워크 연결이 없다. 넘기기 전에 사람이 본다 |
| 읽기 전용 피드(허브가 전용 토큰으로 TestScope 를 조회) | 허브 → TestScope PC 로 들어오는 접속을 연다 — 방화벽 · 토큰 관리 검토 필요 |

검토가 끝나면 그 결정을 새 ADR 로 남기고 이 문서를 가리킨다.

## 결과

- 허브 수신 모듈 · 허브 토큰 · `/api/core` 클라이언트를 만들지 않는다. 다른 문서(요청서 ·
  ReportArchive 설계)가 TestScope 를 수신 대상으로 적고 있어도 이 결정이 우선한다.
- 허브 담당에게 요청서 §12 교환 양식으로 「TestScope 수신 대상 없음 — 보안 사유」 를 회신한다.
- 결정을 바꾸려면(예: 보안 검토 후 수신 허용) 이 ADR 을 대체하는 새 ADR 을 쓴다.
