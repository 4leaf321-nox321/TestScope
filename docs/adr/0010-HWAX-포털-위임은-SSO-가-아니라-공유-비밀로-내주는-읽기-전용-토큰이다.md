# 0010. **HWAX 포털 위임은 SSO 가 아니라, 공유 비밀로 내주는 읽기 전용 토큰이다**

## 결정

HWAX 포털의 MCP 게이트웨이가 TestScope 도구를 **그 사람 명의로** 부를 수 있게,
표준 위임 창구 `POST /api/auth/sso`(+ `/verify` · `/revoke`)를 연다 — 계약은 포털
요청서(HWAXPortal `docs/sso-delegation/ra-request.md`) 그대로이고, Report Archive 가
2026-10-03 에 같은 계약으로 먼저 붙었다(`gateway_token.py` v0.171.1).

> **게이트웨이가 공유 비밀로 「이 사람」 을 말하면, TestScope 에 이미 있고 승인된 그
> 사람의 개인 토큰(`tsc_pat_`, 읽기 전용, 2일)을 내준다.** 계정은 만들지 않는다.

넷을 못 박는다.

1. **SSO 가 아니다.** 포털에 로그인했다고 TestScope 에 들어오지 않는다. 브라우저 길은
   종전대로 TestScope 로그인뿐이고, 이 창구는 **이미 있는 계정**에 토큰을 내줄 뿐이다.
2. **계정을 만들지 않는다**(RA 와 다른 점). TestScope 는 가입 → 관리자 승인 → 부서
   배정의 절차가 있다. 없는 사람·승인 대기·정지는 **403** 으로 답한다. 404 는 「창구
   꺼짐」 전용이다 — 게이트웨이가 404 를 그렇게 읽고 등록 토큰으로 내려가므로, 사람
   하나의 거절을 404 로 내면 창구 전체가 꺼진 줄 안다(RA 가 겪고 고친 자리).
3. **읽기 전용이다**(RA 와 다른 점). 범위를 `read` 로 고정한다. 쓰기가 필요하면 종전처럼
   TestScope 에서 발급한 토큰을 쓴다.
4. **직전 토큰은 폐기하고 새로 낸다** — 지우지 않는다. 「언제 누가 받아 갔나」 가
   「내 정보 › 토큰」 과 감사(`pat.issued_for_gateway`)에 남는다.

## 배경

지금까지는 사람마다 TestScope 에서 토큰을 발급해 포털 「개인 토큰 › 외부 연결」 에
붙여 넣었다(HWAX `connections.py` 의 `testscope` 길). 되긴 하지만 셋이 걸렸다 — 사람이
토큰을 눈으로 보고 옮긴다 · 만료되면 다시 한다 · **쓰기 범위를 켠 토큰을 붙여 넣어도
막을 길이 없다**(사용자가 「HWAX 에는 읽기만」 을 정했는데 강제할 자리가 없었다).

포털 쪽 선택지는 셋이었다.

| | 사용자가 하는 일 | 대가 |
|---|---|---|
| ① 붙여넣기(지금) | 발급 → 복사 → 붙여넣기 | 번거롭고, 범위를 못 강제한다 |
| ② 동의 후 넘겨받기(OAuth 인가 코드) | 「연결」 → TestScope 로그인 → 「허용」 | 양쪽에 화면·API 를 새로 만든다 |
| ③ 서버끼리 자동 발급(ste 방식) | 없음 | 공유 비밀 하나가 **모든 사용자의 토큰을 만들 수 있는 열쇠**가 된다 |

사용자가 **③** 을 골랐다 — "reportarchive 처럼 … 공유코드를 통해 mcp 연결만". HWAX 쪽은
이미 그 길을 열어 두었다(게이트웨이 `provision-config.sh` 의 `TESTSCOPE_SSO_SECRET` →
`per_user_sso.testscope`, 2026-10-03 07:08). 그래서 TestScope 쪽만 만들면 된다.

## ③ 의 위험과, 그래서 좁힌 것

③ 의 위험은 **누구의 토큰을 만들지를 포털이 정한다**는 것이다. 비밀이 새면 그 값을 가진
쪽이 관리자를 골라 그 사람 토큰을 받고, 포털 계정이 털리면 그 사람 이름의 TestScope 토큰이
나간다. 권한 분리 자체는 그대로 돈다(토큰은 그 사람을 못 넘는다) — 어느 권한을 쓸지를
남이 고르게 되는 것이 문제다. 관리자만 보는 **읽기**도 있다(`GET /accounts` 의 전체
이메일, `GET /audit/access` 의 접근 로그).

그래서 ③ 을 그대로 두지 않고 셋으로 좁혔다.

- **읽기 전용 고정** — 쓰기는 이 길로 아예 안 나간다.
- **계정 생성 없음** — 포털 쪽 실수·탈취로 TestScope 에 없는 사람이 생기지 않는다.
- **`HEAX_SSO_ALLOWED_IPS`** — 게이트웨이 박스에서만 부르게 묶을 수 있다.

남는 위험은 적어 둔다: 비밀을 가진 쪽은 **TestScope 에 있는 아무 활성 계정(관리자 포함)의
읽기 토큰**을 받을 수 있다. 그것이 ③ 의 값이고, 사용자가 알고 고른 것이다. 더 좁히려면
②로 가야 한다.

## 대안 — 그때 안 고른 것

- **JIT 로 계정 만들기**(RA·KooRemapper 는 한다). 승인 절차를 우회한다. `pending` 으로
  만들면 어차피 토큰을 못 준다. 뺐다.
- **`X-Heax-Client` 허용 목록**(KooRemapper). 임의 client 이름이 토큰을 무한히 늘리는 것을
  막는 장치인데, 여기서는 같은 이름의 직전 토큰을 폐기하므로 client 마다 하나뿐이다.
  목록을 두면 포털이 client 를 하나 더할 때마다 TestScope 를 고쳐야 한다. 뺐다.
- **토큰 행을 지우기**(RA). TestScope 의 폐기는 `revoked_at` 이고, 목록에 남는 것이
  「누가 언제 받아 갔나」 의 유일한 흔적이다. 폐기로 뒀다.
- **JWKS 로 포털 토큰을 직접 검증**(PAT 없이). 그것은 API 에서 포털의 신원 판정을
  믿는 것이라 사실상 SSO 다. 원하는 것과 반대라 뺐다.

## 결과

- `backend/app/modules/auth/gateway_token.py` — 창구 셋. `routes.py` 가 얇게 건다.
- 설정 `HEAX_SSO_SECRET`(비면 창구 없음 · 404) · `HEAX_SSO_ALLOWED_IPS`.
- 오류 코드 `TSC-AUTH-0200`~`0206` — 꺼짐 · IP · 비밀 · 이메일 없음 · 형식 · 계정 없음 ·
  계정 못 씀.
- 감사 `pat.issued_for_gateway`(그 사람 명의, client, IP, 폐기한 직전 토큰 수).
- 켜는 순서는 **TestScope 먼저** — 포털 쪽에 비밀이 생기는 순간 위임 전용이 된다
  (배포.md 「HWAX 포털에서 붙게 하려면」).
- 시험 `tests/api/test_gateway_token.py` — 계약 모양 · 읽기 전용 · 403/404 가름 · 계정
  안 만듦 · 폐기 · 감사.
