# 사내 신뢰성 시험 반입 준비

사내 시험 절차와 그 결과를 TestScope 에 넣기 전에, 무엇을 모으고 어떤 모양으로 만들어야 하는지.
문서로만 있는 시험을 구조(온톨로지)로 옮기는 방법과, 먼저 정해야 할 것. 2026-09-13.

카탈로그를 들일 때 쓴 원칙이 그대로 적용된다 — 모르면 비워 둔다, 정본은 파일, 기계는 초안,
사람은 고른다, 누가 정했는지 남긴다.

## 1. 무엇이 들어오는가 — 세 덩어리

지금 TestScope 는 세상에 있는 것(카탈로그의 장비·규격·시험 항목·물성)과 우리가 가진 것(보유
장비)을 잇는다. 사내 신뢰성 시험은 그 사이에 없던 세 덩어리를 더한다.

| 덩어리 | 무엇 | 예 | TestScope 의 어디에 붙나 |
|---|---|---|---|
| ① 사내 시험 정의 | 우리 회사가 정한 시험 절차 하나 — 코드·판·조건·판정 기준 | 「MX-REL-012 열충격 (−40 ↔ 85 °C, 500 cy)」 | 시험 항목(온톨로지) + 조건 + 참조 규격에 잇는다. 「이 시험을 할 수 있는 장비」 검색이 그대로 된다 |
| ② 시험 결과(건) | 그 시험을 어느 제품에 언제 어떤 장비로 했고 어떻게 나왔나 | 「2026-08-12 · 모델 A 시료 8개 · 챔버 MT-0031 · 합격, 1개 외관 변색」 | 보유 장비(자산번호)·사내 시험·제품에 잇는다 |
| ③ 측정값 | 결과 안의 숫자 — 시료별·항목별·시점별 | 「시료 3 · 접착 강도 · 시험 후 · 12.4 N」 | 물성/특성 사전에 잇는다 — 「이 제품의 시험 후 접착 강도」 를 물을 수 있게 |

①이 없으면 ②는 자유 텍스트 로그일 뿐이고, ③이 없으면 결과는 합격/불합격 도장일 뿐이다. ①부터 만든다.

## 2. 사내 시험 정의의 속성 — 통상 이 범위

규격서(사내 표준·시험 사양서)를 읽어 뽑아낼 것. **필수** 는 없으면 검색·결과 연결이 안 되는 것,
**권장** 은 있어야 쓸모가 커지는 것, **나중** 은 있으면 좋은 것.

### 식별

| 속성 | 뜻 | 급 |
|---|---|---|
| 사내 코드 | 문서 번호. 「MX-REL-012」 — 이것이 정본 열쇠. 이름은 바뀌어도 코드는 안 바뀐다 | 필수 |
| 판(개정) | Rev. C 처럼. 결과는 어느 판으로 했는지가 남아야 한다 — 조건이 바뀌면 옛 결과와 비교가 안 된다 | 필수 |
| 이름 · 별칭 | 문서 제목 + 현장에서 부르는 말(「열충격」 「TS」). 별칭이 곧 검색어 | 필수 |
| 소유 부서 · 담당자 | 누가 이 절차를 고치나 | 권장 |
| 상태 · 제정/개정일 | 현행 / 폐지 / 초안 | 권장 |
| 원본 문서 | PDF/링크. 화면에서 원문을 볼 수 있어야 검토가 된다 | 필수 |

### 분류

| 속성 | 뜻 | 급 |
|---|---|---|
| 시험 항목 | 온톨로지의 시험 항목 코드(thermal_shock …). 하나 이상. 복합 시험(온습도 + 진동)은 둘 다 | 필수 |
| 시험 목적 | 신뢰성(수명) / 환경 내성 / 안전 / 성능 / 외관 — 결과를 읽는 눈이 다르다 | 권장 |
| 적용 대상 | 제품군 · 부품 · 재료 중 무엇에 하는 시험인가. 제품군 사전이 필요하다(4절) | 권장 |
| 개발 단계 | EVT/DVT/PVT/양산 — 어느 때 하는 시험인가 | 나중 |

### 근거

| 속성 | 뜻 | 급 |
|---|---|---|
| 참조 규격 | IEC 60068-2-14 Na, JESD22-A104 … — TestScope 의 규격(시험법)에 잇는다. 사내 시험은 대개 외부 규격을 좁힌 것이라, 이 연결이 있으면 규격의 요구 조건을 상속받는다 | 필수 |
| 고객 요구 · 사내 기준서 | 「고객 X 스펙 4.2」 — 왜 이 조건인지의 출처 | 권장 |

### 조건 — 검색과 장비 매칭이 여기서 갈린다

| 속성 | 뜻 | 급 |
|---|---|---|
| 조건 값 | 조건 사전(시험 조건 정의)의 키로: 온도 −40~85 °C, 습도 85 %, 가속도 20 g, 전압 5 kV … 사전에 없는 키는 검토함 「새 시험 조건」 으로 만든다 | 필수 |
| 프로파일(단계) | 온도 사이클처럼 단계의 순서가 있는 시험: 「−40 °C 30분 → 85 °C 30분 × 500」. 검색은 양끝(envelope)만 보고, 프로파일 자체는 절차로 남긴다 | 권장 |
| 지속 시간 · 사이클 수 | 96 h, 500 cy — 장비 예약과 결과 비교의 단위 | 필수 |
| 시편 | 수량, 전처리(컨디셔닝), 장착 방향, 통전 여부(동작 중/비동작) | 권장 |
| 측정 시점 | 전/중(인터벌)/후 — 「시험 후 측정」 이 대부분이지만 중간 측정이 있는 시험은 결과 모양이 다르다 | 권장 |
| 장비 요구 | 따로 적지 않는다 — 시험 항목 + 조건이 곧 장비 요구이고, TestScope 가 「되는 장비」 를 찾는다. 다만 「챔버 내부 300 mm 이상」 같은 공간 요구는 사양 조건으로 | 나중 |

### 판정과 산출물

| 속성 | 뜻 | 급 |
|---|---|---|
| 측정 항목 | 무엇을 재서 판정하나 — 접착 강도, 절연 저항, 외관, 기능 동작. 특성 사전의 키로(물성 사전 + 제품 특성) | 필수 |
| 합격 기준 | 항목마다: 한계값(≥ 10 N, ≤ 10 % 변화율), 등급(크로스컷 1급 이상), 정성(균열 없음). 변화율 기준은 「시험 전 대비」 라 시험 전 측정이 있어야 한다 | 필수 |
| 결과 형식 | 수치 / 등급 / 합불 / 사진 — 결과 표를 어떻게 받을지 정한다 | 권장 |
| 불량 모드 사전 | 변색·균열·박리·단선·기능 불량 … 결과에 「무슨 불량」 을 적는 통제 어휘 | 권장 |

## 3. 시험 결과(건)의 속성

결과는 **시험 건(run) 한 줄 + 측정값 여러 줄** 두 층으로 뽑는다. 엑셀이면 시트 둘, 리포트 PDF 면 표 둘.

| 층 | 속성 | 급 |
|---|---|---|
| 시험 건 | 의뢰/성적서 번호 — 열쇠 | 필수 |
| | 사내 시험 코드 + 판 | 필수 |
| | 대상: 제품 모델(코드) · 로트/배치 · 시료 수 · 시료 ID 체계 | 필수 |
| | 실제 조건 — 계획과 다르게 했으면 그 값(챔버 실측 로그가 있으면 링크) | 권장 |
| | 장비 자산번호 — 보유 장비에 잇는다. 「이 챔버로 한 시험」 · 교정 상태와의 대조가 여기서 나온다 | 필수 |
| | 일자(시작·종료) · 수행자 · 의뢰 부서 | 필수 |
| | 종합 판정 · 판정자 | 필수 |
| | 첨부 — 성적서 PDF, 사진, 챔버 로그 | 권장 |
| 측정값 | 시료 ID | 필수 |
| | 측정 항목(특성 사전 키) · 시점(전/중 n회/후) | 필수 |
| | 값 · 단위 (또는 등급 / 합불) | 필수 |
| | 판정(항목별) · 불량 모드(사전 키) · 비고 | 권장 |
| | 측정 장비 자산번호(시험 장비와 다를 때 — 인장기·저항계) | 나중 |

결과 데이터를 뽑을 때 가장 자주 깨지는 것 셋.
① 제품 식별이 자유 텍스트(「A모델 신형」)라 같은 제품이 다섯 이름으로 갈린다 → 제품 코드 마스터가 먼저.
② 시험 코드에 판이 없어 조건이 다른 결과가 섞인다 → 판 필수.
③ 측정값이 리포트 표 안에 가로로 펼쳐져 있다(시료 1~8이 열) → 세로(long) 형식으로 다시 세워야 한다: 한 줄 = 시료 × 항목 × 시점.

## 4. 문서로만 있는 시험을 온톨로지로 — 방법

규격서·사양서는 사람이 읽는 글이라 구조가 없다. 통째로 넣지 말고, **한 시험 = 한 장의 카드** 로
분해한다. 카드의 칸이 곧 2절의 속성이다.

### 카드 한 장 (예 — 실제 문서를 이 모양으로)

```
코드      MX-REL-012 Rev.C        이름   열충격 (현장: TS, 냉열충격)
시험 항목  thermal_shock           목적   환경 내성        대상  모듈·완제품
참조 규격  IEC 60068-2-14 Na · JESD22-A106
조건      온도 −40 ↔ +85 °C · 유지 30 min · 전환 ≤ 10 s · 500 cycle · 비동작
시편      8개 · 전처리 23 °C/50 % 24 h · 측정 전/후
측정 항목  외관(균열·박리·변색) · 기능 동작 · 절연저항 ≥ 100 MΩ · 접착 강도 변화율 ≤ 20 %
판정      전 항목 만족 시 합격 · 1개라도 불량이면 로트 불합격
원문      REL-012_RevC.pdf p.3–5
```

### 절차

1. **문서 목록부터.** 사내 시험 문서가 어디에 몇 건 있는지(문서관리 시스템·공유 폴더·엑셀). 코드 체계가 있는지, 판 관리가 되는지. 이 목록 자체가 첫 산출물이다.
2. **표본 10건을 손으로 카드화.** 부서마다 문서 모양이 다르므로 10건을 사람이 직접 채워 보면 카드 칸이 맞는지, 무엇이 안 들어가는지 드러난다. 여기서 칸을 고친다 — 나중에 고치면 100건을 다시 한다.
3. **사전 넷을 세운다.** 시험 항목(있음 — 96종, 사내 이름은 별칭으로), 시험 조건(있음 — 12종, 모자라면 검토함 「새 시험 조건」), 특성(물성 사전 271종은 재료 물성이라 제품 특성 — 절연저항·기능 동작·외관 — 이 없다. 축을 하나 더 세운다), 불량 모드(새로), 제품군/제품 코드(새로 — 회사 마스터를 가져온다).
4. **나머지는 기계가 초안, 사람이 확인.** PDF → 텍스트 → 카드 초안(LLM)을 만들고, 카탈로그와 같은 방식으로 원문 쪽 번호·확신도를 붙여 검토함에 세운다. 시험 항목 매핑·조건 키 매핑·참조 규격 매핑이 각각 한 물음이 된다. 사람은 고르기만 한다.
5. **정본은 파일로.** 카드는 `source/internal_tests/<코드>.json` 같은 정본 파일로 두고 반입한다 — 카탈로그와 같은 길. 문서가 개정되면 파일의 판이 오르고, 옛 판의 결과는 옛 판에 남는다.
6. **결과는 표로 받는다.** 시험 건 표 + 측정값 표(세로 형식)를 붙여넣기 반입으로. 제품 코드·장비 자산번호·시험 코드+판이 마스터에 없으면 줄이 붉게 뜨고 안 들어간다 — 장비 대장 반입과 같은 규칙.
7. **파일럿 왕복.** 한 부서 · 시험 5~10종 · 최근 결과 50건으로 「문서 → 카드 → 반입 → 되는 장비 검색 → 결과 조회」 를 끝까지 한 번 돈다. 여기서 안 맞는 칸이 다 나온다.

## 5. 먼저 정해야 하는 것 (사람의 결정)

| 결정 | 왜 | 고를 것 |
|---|---|---|
| 사내 시험 코드의 정본 | 열쇠가 둘이면 결과가 갈린다 | 문서관리 시스템 번호 / 별도 부여 |
| 제품·시료 식별 마스터 | 결과의 「무엇에」 가 자유 텍스트면 비교가 안 된다 | ERP/PLM 제품 코드 가져오기 / 사내 시험용 코드 새로 |
| 특성 사전의 범위 | 재료 물성(MaterialTwin 키)과 제품 특성(절연저항·기능)을 한 축에 둘지 둘로 나눌지 | 한 축 + 종류 표시 / 두 축 |
| 결과 공개 범위 | 부서 것인가 전사 것인가 — 장비는 부서 소유 모델이다 | 부서 소유 + 열람 허용 / 전사 공개 |
| 원본 보관 | PDF 를 시스템에 넣나(첨부) 링크만 두나(문서관리 시스템) | 첨부 / 링크 / 둘 다 |
| 온톨로지의 이름 | 사내 시험 이름으로 시험 항목을 늘릴지, 기존 항목에 별칭으로 붙일지 | 별칭 우선(권장) — 항목이 늘면 검색이 흩어진다 |

## 6. TestScope 쪽에서 준비할 것

- **사내 시험 정의 모듈** — 카드 그대로의 표(코드·판·시험 항목들·조건 envelope·프로파일 단계·측정 항목·기준·참조 규격·원문). 「되는 장비」 검색은 시험 항목 + 조건으로 지금 검색을 그대로 부른다.
- **시험 결과 모듈** — 시험 건 + 측정값(세로). 붙여넣기 반입(장비 대장과 같은 틀), 성적서 첨부.
- **사전 셋** — 특성 · 불량 모드 · 제품군/제품. 기준정보 축으로 세우면 편집 화면·별칭·쓰임 내역이 그대로 따라온다.
- **검토함 물음 셋** — 카드 초안의 시험 항목 매핑 · 조건 키 매핑 · 참조 규격 매핑.
- **「신뢰성 시험」 화면**(지금 비어 있는 메뉴) — 시험 항목 × 부서가 아니라 사내 시험 × 제품군 표가 더 맞을 수 있다. 파일럿 뒤에 정한다.

## 7. 순서 제안

1. 문서 목록 + 결과 데이터가 어디 어떤 모양으로 있는지 조사 (한 부서, 1주)
2. 표본 10건 카드화 → 카드 칸 확정 → 5절의 결정
3. 사전 셋 세우기 (특성·불량 모드·제품)
4. 사내 시험 정의 모듈 + 반입 + 검토함 물음
5. 결과 모듈 + 반입
6. 파일럿 왕복 50건 → 고치기 → 다른 부서로
